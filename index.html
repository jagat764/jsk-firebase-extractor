How these links are structured

The ?s= parameter is UTF-8 Base64. After decoding it usually looks like this:

FIREBASE_URL | CREDENTIAL | EXPIRY_MS | OPTIONAL_DEVICE_ID

https://project-default-rtdb.firebaseio.com | KEY | 1793105515015 | device-123

Fields may be separated by a single | or by the older triple ||| separator — both formats are decoded the same way.

  • • Field 1 — Firebase / Realtime Database endpoint.
  • • Field 2 — database secret, API key, or short credential.
  • • Field 3 — expiry timestamp in milliseconds (10-digit seconds also work).
  • • Field 4+ — optional device ID or reference.

Some apps — such as VANTAGE share links — wrap the same details as Base64 over an XOR-encoded JSON object instead:

base64url( XOR( {"u":"FIREBASE_URL","k":"CREDENTIAL","l":"LABEL","e":EXPIRY_MS} ) )

Those links are recognised automatically as a VANTAGE share link and yield the same endpoint, credential, label and expiry fields. "e":0 means the link never expires.

Privacy: everything runs in your browser. The tool never connects to a Firebase database, never tests credentials, and never uploads pasted data.
